# Meena Time — برنامج الحضور والانصراف (نسخة سطح المكتب)

نسخة ويندوز تُشترى مرة واحدة من نظام الحضور، بتصميم «Apex Time» ونفس قواعد الحساب في النسخة السحابية. تعمل على جهاز واحد بدون إنترنت، وتقرأ البصمات من أجهزة ZKTeco على الشبكة المحلية أو من ملف.

## التقنية
- **Electron** + واجهة HTML/CSS/JS بدون إطار عمل (`renderer/`).
- **sql.js** (SQLite داخل البرنامج) — ملف واحد `meena-time.sqlite` في `%APPDATA%\Meena Time`، يُحفظ بعد كل عملية (كتابة ذرّية)، ونسخة احتياطية تلقائية يومياً (آخر 30).
- **node-zklib** لقراءة أجهزة البصمة (TCP/UDP 4370)، **xlsx** لتصدير Excel، و`printToPDF` في Chromium لملفات PDF.

## الهيكل
| المسار | المحتوى |
|---|---|
| `main.js`, `preload.js` | عملية Electron الرئيسية: قاعدة البيانات، الترخيص، الجهاز، الحفظ/PDF، النسخ الاحتياطي |
| `lib/license.js` | الترخيص المرتبط بالجهاز (Ed25519): «كود الطلب» ← «كود الترخيص» |
| `renderer/engine.js` | محرك الحساب: الورديات (حتى 4 + شفت ممتد)، الدوام المفتوح، الورديات المتغيرة، رمضان، الترحيل |
| `renderer/db.js` | المخطط والترحيل من الإصدارات السابقة (دمج قواعد السنوات القديمة) |
| `renderer/windows/*.js` | شاشة لكل قسم (البيانات الأساسية، الموظفين، المواعيد، الإجراءات، التقارير، الإعدادات، الدليل) |
| `installer/installer.nsi` | برنامج التثبيت (NSIS) |
| `tools/` | أدوات المطوّر فقط — لا تُضمَّن في البرنامج |

## أوامر المطوّر
```bash
npm install
npm start                                   # تشغيل البرنامج
npm run demo                                # تشغيل بالبيانات التجريبية (tools/demo-data.sqlite) — دخول: أ / 1234، كل المزايا مفتوحة، بيانات منفصلة في «Meena Time Demo»
xvfb-run -a node tools/full-test.mjs        # الاختبار الشامل (219 فحص على البرنامج الحقيقي)
xvfb-run -a node tools/merge-test.mjs       # اختبار دمج قواعد بيانات الإصدارات القديمة
xvfb-run -a node tools/perf-test.mjs        # الأداء على 200 موظف × سنة
# بناء برنامج التثبيت (بدون wine):
npx electron-builder --win dir --x64 && (cd installer && makensis -DVERSION=1.0.0 installer.nsi)
```

## الربط بالموقع (من 1.1.0)
الموقع (Frappe) هو مصدر البيانات: الإدارات والوظائف وأنواع الإجازات والمشاريع والمجموعات والعطلات والدوامات (بمواعيدها) والموظفين وتاريخ دواماتهم والإجازات والأذونات المعتمدة وحركات البصمة تنزل للبرنامج؛ والحركات المقروءة هنا (جهاز/ملف/يدوي) تُرفع كـ Employee Checkin. أثناء الربط تُقفل شاشات الإعداد هنا. المزامنة عند الدخول وكل 10 دقائق وبعد قراءة الحركات، ومن شريط «مرتبط بالموقع» أسفل الشاشة.
- مستخدم الربط على الموقع: `sudo -u frappeuser <bench>/env/bin/python tools/create-sync-user.py <site> <url>` → ثلاث قيم تُلصق في «الإعدادات ← الربط بالموقع».
- الرمز السري في `web-link.json` بمجلد البيانات (مشفّر بـ safeStorage إن توفر) — لا يدخل قاعدة البيانات ولا النسخ الاحتياطية.
- اختبار: `xvfb-run -a node tools/sync-test.mjs` (على `tools/mock-frappe.mjs`).
- الدوامات المتغيرة على الموقع تصل عبر Shift Assignment المؤرخة (الفجوات = «راحة (من الموقع)»).

## إصدار ترخيص لعميل
```bash
node tools/keygen.js <كود-الطلب> Gold
```
المفتاح الخاص `tools/keys/private.pem` **غير موجود في git** — احتفظ بنسخة منه في مكان آمن؛ فقدانه يعني عدم القدرة على إصدار تراخيص جديدة.

## حدود معروفة
- يعمل على جهاز واحد (لا يشارك قاعدة البيانات على الشبكة بين عدة أجهزة).
- ملف التثبيت غير موقّع رقمياً، فيظهر تحذير Windows SmartScreen عند أول تثبيت («More info ← Run anyway»).
- لم يُختبر بعد على جهاز بصمة حقيقي.
